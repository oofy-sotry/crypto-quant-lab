## 2026-10-24 — 1단계 D4 재처리

**Claude Code에게 맡긴 것**
- `ReprocessRun` 모델, 재처리 대상 3개(분봉 재수집·재집계·일봉 재수집), 원본·DB 비교 후 다른 것만 반영, (종목, 날짜)별 advisory lock, dry-run·실패 롤백, 커맨드 `reprocess`, `POST/GET /api/reprocess/`와 테스트
- 집계 함수 보강: 추가/변경 구분(`RETURNING xmax = 0`), 분봉이 사라진 구간의 집계 삭제
- 실데이터 시나리오(BTC 분봉 1시간 삭제 → 탐지 → dry-run → 복구 → 재실행)와 D2 기준 해시 비교, 로컬 서버로 동시 요청 409 확인
- 전체 테스트에서만 실패하는 테스트 원인 분석(transaction=True 테스트의 테이블 비우기)
- README·ROADMAP 반영

**직접 확인·결정한 것**
- 재처리 대상을 분봉·집계·일봉 3가지로 결정(일봉 재처리로 캐시 무효화를 기능으로 보여 주기)
- 인증은 관리자 토큰 + `requested_by` 입력, API·커맨드 모두 dry-run 기본으로 결정
- 실데이터 복구 시나리오(BTC 분봉 1시간 삭제 → 이슈 탐지 → dry-run → 복구)에서 복구 후 해시가 D2 기준과 같다는 결과 확인
